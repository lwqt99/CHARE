# 实现范围与写作口径

此版本是 `CHARE-RATIONAL-BASE-PBC-v1` 的实际 Go/PBC 研究原型，采用对称 Type A、独立 Ed25519 认证及域分离 SHA-256 交付/KEM。数学依据仍是注明条件的 GBGM＋ROM 证明。实际曲线和哈希的运行测试不能验证该证明，也不自动给出具体安全位数。

实现 v0.5.1 补齐改变候选集合与重新授予两个压力分支的实际公开发送者入口，具体认证、数据绑定和计费见 SENDER.md。加密核心、取样规则、现有参数配置和真实注册关系未更改。压力分支是独立的额外工作负载，不替代连续 N 次有效撤销和 N 次获取。

已实现真实设置、公钥与全部投影、发行及 source-DH 私密标量交付、完整配对验证、固定集合和记录字典的公开矩缓存、策略权重、帮助生成及验证、封装和局部解封装。公共聚合不接收用户秘密或发行掩码。未实现任意敌手字节流的安全曲线点解码；输入是同一个实际 PBC 上下文中生成的类型化对象。

每个批量案例包括初始化、全员首次获取、A/B/合取/负文字、公开转录依赖的交错更新与获取、最后全员追赶及旧状态保持。更新主负载使用机构在持有人离线时发行新的**有效拒绝记录**；新胶囊在获取时才实际解开。额外压力项包括签名公开批量状态后的不同候选集合重建，以及重新授予的新版本发行。这些是明确的合成调度，不是通用分布式时钟、分叉检测或网络服务实现。

不同集合的批量失效压力项是一个独立分支；它不取代主负载的全槽位缓存。之后的正向新版本测试从主负载中实际处于拒绝状态的槽位出发。两项不能被描述为同一连续全局历史中的“失效再恢复”。

首次获取采用已经验证的目录及认证的公开验证缓存。每个客户端实际核验签名、交付和帮助方程；不重复免费假定客户端重验全目录。`cold_audit / stress_one_client` 实际重做一个客户端的全目录检查。它不等于实测全员冷审计。下载用实际序列化及内存复制计字节，不模拟网络带宽或网络时延。

`snapshot` 包含认证的 `VerifierBytes`，使帮助检查所用的公开和、槽位和 R 值具有明确交付来源。本配置采用论文单列的认证聚合服务口径；独立冷审计另计。认证只说明指定密钥签署了这些字节，不能单独证明现实资格、当前性或无分叉。

当前编码刻意保留完整上下文：参数、根、记录和历史更新实际序列化、复制和哈希。两点只描述代数密文核心；完整密文和在线处理包含这些额外字节，不能写成端到端常数大小或常数时间。全目录记录保持二次规模，全员获取完整清单可达三次累计字节。数据中的重复字段不得事后删掉再称实测。

v0.2.0 增加双方共有的实际认证前缀缓存，并保留原完整传输作为参照。热包省略已安装前缀，接收方恢复完全相同的原密文字节；所有原 KDF 输入不变。发布、N 次实际客户端安装、包生成和单客户端恢复分别测量。每个策略另做一次新鲜封装验证复用，不复用原密文冒充新封装。完整说明及网络/本地内存字节的区别见 TRANSPORT.md；原生验证状态仍以 VALIDATION.md 为准。

普通 source-DH 对照获得自己的短上下文，不被迫携带 CHARE 的投影数组。它使用显式授权名单、一个实际 DH 头和 n−1 个实际密钥包装；名单由合成正确性检查器提供并单独记行。它没有实现隐藏资格筛选。因此只能用于已说明条件的数据面比较，不能据此声称完整功能等价或端到端优势。双方名义参数相同也不构成同安全强度证明。

v0.3.0 的 DH 对照独立生成基点、接收密钥和认证密钥，实际执行注册、证书分发、授权名单版本发布、全员首次获取、离线追赶和历史保留。`CHARE-auth` 只属于 CHARE；DH 的认证与缓存分别计费。完整算法、实际费用及外部名单前提见 [对照生命周期](BASELINE_LIFECYCLE.md)。`authorized_list_test_oracle` 仍是合成输入准备，不能当作隐藏资格选择服务。两个完整的已实现流程也不自动成为同功能、同安全目标比较。

`raw.csv` 记录各操作的局部实测区间，内部配对和源群计数来自实际执行计数器；目标群操作另在 detail 中记录。原始序列化大小不是 Go/C 堆内存占用。未计时的字节观察标为 `no timing sample`，汇总和绘图不得将其作为 0 ms 性能样本。功能断言和额外检查不全属于计时区间，不应把局部区间简单相加当作完整进程运行时间。

批处理只使用程序内明确生成的合成资格。当前单记录 `certify_and_deliver` 的源群操作数为 `4N+2Ny`，其中 `y` 是该条资格位；因而逐记录计数本身会暴露这个合成位。不能把这些结果日志用作真实私密资格的公开遥测。论文的公开转录隐私不包含任意发行侧操作轨迹或计时侧信道，本原型也不声称常数时间、生产部署加固或物理内存安全。补做空操作并不能自动证明不存在侧信道。

设置标量没有保存在公开参数对象中，但 Go/C 垃圾回收不保证物理内存安全擦除。程序不输出秘密随机带、用户秘密或掩码；实际公共参数和环境会随结果回传。

取样实现保留全域与非零域区别。外层非零标量、排除槽位的 tau 和非单位生成元检查各有 1024 次上限；失败时返回错误，不替换为固定秘密。Go 标准库 `crypto/rand.Int` 自己还有字节级拒绝循环，因此外层上限不代表绝对的随机字节读取次数或最坏运行时间上限。取样分布的对应说明以独立均匀熵源及正确原生群取样为前提；系统随机源错误另行报告，不能由功能测试推断其概率。

首次在虚拟机执行必须先通过 `go test ./... -count=1`；启动脚本已经包含此门槛。v0.3.0 新增对照状态机检查，历史 v0.2.1 的 36 项测试及 252 项案例检查不能替代新版验证。具体新旧原生测试、兼容修复和失败记录见 VALIDATION.md 和 PBC_WINDOWS.md。你的虚拟机完整网格运行、具体曲线安全强度校准及同安全目标完整系统比较仍未完成。
