# 发送者的实际公开状态获取

v0.5.0 增加 `sender_snapshot_acquisition`。每个主策略在初始化后和有效撤销序列后，各执行一次完整获取。随后 `prepare_policy` 从独立复制的公开状态生成目标，不使用目录的矩缓存、用户秘密、资格真值或私密交付。

复制内容包括公开设置引用、组内槽位、版本、聚合标识、各基项的和、W 的和，以及实际加密使用的完整追加上下文。设置对象在本进程中按不可变对象共享；其完整序列化仍在取得的快照中。复制源群点、复制字节和实际签名核验均在计时范围内。

快照格式升为 `CHARE/full-current-snapshot/v2`，新增完整 sender 字段。原 `VerifierBytes` 没有包含 target 使用的追加上下文，不能单凭它认证所有发送者输入。新格式把这些字节一起签名。此变化只改变应用绑定上下文，不改变原群运算、随机权重、KDF 或证明假设；v0.4.1 旧结果保留原格式，不能与 v0.5.0 混合。

获取按顺序执行：

1. 使用独立固定的发行公钥验证快照签名。
2. 从输入的类型化公开对象重建规范快照，与已签名字节逐字节比较。
3. 复制发送者所需的公开状态，复核其序列化与已绑定字段相同。
4. 返回复制的上下文及实际获取帧；封装只使用这些已核验的材料。

这是生成的类型化对象之间的真实执行，不是任意恶意网络字节的解码器。认证服务已经负责注册检查与快照发布；发送者不重复全目录冷审计。签名不证明当前性或无分叉；当前版本仍由既定可信快照入口选择。

`bytes` 是实际 `CHARE/sender-acquisition/v1` 帧长度，包含完整快照及签名。快照中包含完整原始记录、验证字段及 sender 字段，重复出现的公开字节按实际帧计费，不扣成理论最小编码。本轮不添加发送者缓存，不宣称这是最小下载量。双方已有的密文前缀缓存另列。

`sender_acquisitions.csv` 是原始测量的独立视图。它包含 DH 初始化注册表、双方各主策略的实际发送者获取，以及已有的 DH 重新授予压力行。DH 初始化注册表一行已计入初始化阶段，不能把整张发送者表再次加到初始化总量。主策略的获取在主生命周期两阶段之外单独收费。CHARE 改变候选集合、重新授予的压力分支仍为直接类型化功能检查，不以此声称完成所有部署入口测量。

测试只验证实现一致性：公用状态复制后的加密结果一致；目录更新不改变既有复制；有效签名与错误状态不能混用；未认证时不先做群运算；没有持有人秘密也可封装。它们不是安全证明或性能结论。

## v0.5.1 压力分支补齐

上述压力入口缺失是 v0.5.0 的边界。v0.5.1 对 `stress_changed_cohort_A` 和 `stress_regrant_A` 都实际执行发送者获取、策略准备和封装。CHARE 的前一个分支额外发布 `CHARE/cohort-sender-snapshot/v1`：绑定完整父快照及签名、公开失效事件及签名、重建后的 VerifierBytes 和 SenderBytes。获取方先验证三份签名，再核对父状态、事件中的有序槽位与完整类型化发送者材料，最后复制独立公开状态。不能把分支快照当成主历史快照。

父状态、事件和聚合内容都属于公开输入；获取不使用持有人秘密或资格真值。认证聚合服务与可信当前分支选择仍是前提；签名不额外证明聚合正确性、真实到期或无分叉。所有签名、完整重复父字节、复制和公开比较实际收费。分支发布缓冲区独立列为 `retained_history_storage / stress_branch_publication`。

重新授予分支使用已更新主快照的原获取流程。显式名单 DH 对照同时新增改变集合后的实际授权视图获取；名单为空时核验并收费，按原定义不运行无接收者的 DH KEM。其授权视图格式升为 v2，把历史分支直接纳入每个视图的签名消息，防止同版本视图在不同历史间移植；总清单的原分支绑定仍保留。这不是分叉检测或新鲜性协议。

两个方案的压力行保留在原始测量与发送者表中，不并入初始化或 N 次撤销／获取主负载，不混合 v0.5.0 结果。本补充仍是类型化对象执行，不是恶意网络字节解析器，也不新增发送者缓存或性能优势主张。
