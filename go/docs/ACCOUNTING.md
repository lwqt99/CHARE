# 完整负载的实测汇总

v0.4.1 补齐了测量路径中的认证检查：目录注册与独立冷审计重验根证书，冷审计也重验当前清单签名；离线追赶在处理私密交付前重验清单签名。使用独立固定的发行公钥，不接受证书自行指定信任根。初始化的签名自检和目录验证是两个实际调用，都计时。原加密骨架、编码、参数配置和撤销调度不变。

这些函数接收已生成的类型化对象，不是任意网络输入的安全解码器。当前性仍由既定可信快照接口提供，签名不证明新鲜性或无分叉。

在本地绘图目录，新增 `summarize_workload.py` 读取完整回传目录：

```text
python [local path removed] <解压后的完整运行目录>
```

它按固定操作清单核对次数：初始化包含完整设置、N 个用户注册、mN 个 CHARE 资格记录、公开验证、聚合/名单发布和 N 次首次获取；动态包含请求数量的实际拒绝记录更新、验证、安装、清单发布和配对的双方获取。CHARE 的 `CHARE-auth` 费用归入 CHARE。若缺少或重复必需操作，拒绝生成阶段总量。

同一行的计时已涵盖其 `count` 个操作，汇总直接相加，不再乘以 `count`，也不先取跨案例均值。先计算每个案例的阶段总量，再报告同配置重复案例的中位数与观察范围；观察范围不是置信区间。

实际返回的零纳秒区间原样保留，并在账本中计数为 `zero_duration_rows`。这不表示操作没有成本，也不能作为无限加速比的分母。本机小规模 Windows 验证已观察到这种现象；正式性能判断需使用目标虚拟机实际计时，不能用估算替换零值。

输出文件：

- `lifecycle_operations.csv`：每个案例、每项必需操作的实际累计时间、输出字节和群运算次数。
- `lifecycle_cases.csv`：各方案初始化、动态阶段的实际计时间隔总和，以及按客户端/发送者角色分开的获取载荷字节。
- `lifecycle_replicates.csv`：同配置跨重复的中位数、最小和最大值。
- `lifecycle_exclusions.csv`：没有混入上述主负载的真实行，包括可选缓存、策略执行、压力分支、存储观察和合成名单测试输入。
- `lifecycle_scope.json`：源码/参数身份、失败与跳过案例、比较范围和仍未实现的费用。
- `sender_acquisitions.csv`：发送者实际获取的独立视图；DH 注册表行已计入初始化，不得重复加入总量。v0.5.0 逐项检查双方各主策略的获取次数和真实载荷。

**计费范围必须保留：**

1. 时间是指定非嵌套操作区间之和，不是网络端到端时延，也不包括全部测试和进程开销。
2. 原始 `bytes` 有生成物、重复序列化、客户端下载等不同含义。只有实际获取载荷按角色相加；不把所有输出字节相加称作网络总流量。
3. 策略准备与封装、可选缓存、重新授予、到期及冷审计各自另列。它们没有被删除，也没有被计为零；不能把这里的两阶段总量称作所有工作负载总成本。
4. DH 对照依赖外部已确定的公开授权名单。合成真值计算不是隐藏资格选择服务，不以其耗时替代未实现的服务。
5. v0.5.0 实际执行主策略发送者的类型化快照获取、认证与独立状态复制，详见 SENDER.md。网络字节解码、协议/重传、完整进程内存，以及改变集合的压力分支部署入口仍未全部实例化。账本明确列出，不补估算。
6. v0.4.0/v0.4.1/v0.5.0 的认证范围和快照格式不同。旧结果可以独立读取，但不得混为同一实现的重复样本。

当前参数只是尺寸配置。实际 `r/q`、参数文件、编码长度及散列均保留；不能用 `r_bits/2` 直接声称整套配对构造的安全位数。正式安全强度校准与实测计时分开验收。
# v0.5.1 压力发送者补充

`stress_changed_cohort_A` 与 `stress_regrant_A` 的 `sender_snapshot_acquisition` 是实际认证及复制后的完整帧长度；对应策略准备、封装、帮助生成／验证和局部解封装分别计时。`CHARE-auth / snapshot_publish / stress_changed_cohort` 是新的完整分支发布，含实际重复的父快照字节。其存储观察不与发布输出或下载简单相加为网络总量。

DH 对照的 `sender_authorization_acquisition / stress_changed_cohort_A` 也实际执行。空授权名单只收费真实取得和验证，不虚构封装观测。两个分支仍与主初始化和 N 次撤销／获取账本分开；`sender_acquisitions.csv` 是同一原始行的视图，不重复加收。
