# 完整密文与认证前缀缓存

从实现 v0.2.0 起，每例同时测量原完整密文与可选的缓存传输。两者是不同交付口径；不能把所有行直接相加为一个协议的网络费用。CHARE 和显式名单 DH 获得同样的缓存工具，DH 保留自身较短的上下文。

加密、解密、随机数分布、完整上下文和 SHA-256 输入未变。缓存将已签名的**原始字节前缀**保存为不可变条目，传输“条目 ID＋剩余字节”，接收方展开后必须与原完整密文逐字节一致。它不是新的密码学构造、KDF 优化或总体压缩结果。策略准备、完整序列化、前缀扫描、恢复和 KDF 仍可能随目录大小增长。

CHARE 的可复用前缀包含完整固定目录、绑定的快照、版本和文字数量；不包含策略坐标、每次目标选择的新权重或新密文点。同一快照、同一文字数的 A、非 A、B 可以共享条目。合取长度改变或快照更新需要新条目。DH 的前缀含其自己的实际应用上下文；v0.3.0 上下文包含签名 epoch 和带接收键的授权视图。密文内的接收者 ID 数组、包装和新头仍保留在每个包中。名单的这些实际重复字节均计费，没有事后去重。

每个方案使用自己的目录认证密钥签署字面 ID 与前缀，没有用免费哈希替代完整绑定。客户端预先固定认证公钥，安装时核对期待 ID 和签名；同 ID 不同前缀拒绝，完全相同条目重放可以接受。期待的当前 ID 仍由可信当前快照提供，签名与缓存不解决当前性或分叉。v0.3.0 的发布方和保留客户端字节分别按 CHARE / DH-explicit-list 记录，不再合并到 shared-transport。

每个首次出现的条目都实际签名一次，对 N 个客户端分别执行字节复制和验签安装。只有首个客户端的缓存跨调用保留，其余安装执行后释放本进程对象。因此测得全部 N 次安装/获取操作，但本进程峰值内存不能冒充 N 台机器的累计缓存占用。每个策略另做一次真正的新鲜封装，复用原冻结目标，确认第二次传输命中缓存；其费用使用独立操作名。

| operation | 实际执行与 bytes 的含义 |
|---|---|
| transport_cache_setup | 固定已有认证公钥；bytes 为公钥交付尺寸 |
| transport_prefix_prepare | 完整序列化并解析复制前缀；bytes 为前缀尺寸，非网络发送 |
| transport_registry_lookup | 比较条目 ID 与实际前缀；bytes 为 0 |
| transport_entry_publish | 签名并保留完整条目；bytes 为一次发布尺寸 |
| transport_entry_install | 每个客户端分别复制、验签、安装；bytes 为该客户端此次实际接收条目 |
| transport_packet_encode | 实际前缀扫描、后缀复制及打包；bytes 为后续传输包 |
| transport_packet_expand | 按期待 ID 取出前缀，复制恢复；bytes 为本地恢复后的完整密文，非第二次网络传输 |
| transport_repeat_encapsulate | 独立新随机量的第二次真实封装；bytes 为原完整密文序列化 |
| transport_repeat_help | CHARE 新鲜封装检查所需的额外帮助生成和公开验证；不计为缓存创造的密码学收益 |
| transport_repeat_decapsulate | CHARE 或 DH 的一次新鲜密文实际解封装 |
| transport_retained_bytes | 发布方及一个保留客户端的实际字节缓冲内容；无计时，不含 Go 对象/映射开销，不是 N 台机器累计内存 |

单个固定条目下，令完整密文大小为 F、前缀 P、每包新增 framing 和 ID 为 h，条目发布大小为 E。发送 L 个密文给一个已经安装该条目的客户端时，热传输为 L(F−P+h)；第一次安装还须加 E。收益条件为 L(P−h)>E，不能仅比较热包和完整密文。若部署要求 N 位用户预取，则安装交付为 N E；还要分别计入服务发布、重复获取和每次快照变化的新条目。上述是费用恒等式，实测表只填本次实际执行的次数与字节，不输出估算时间。

接收包的后缀仍是原 CPA 密文，没有额外签名，不声称恶意密文认证或 CCA 安全。格式解析只处理字节框架；本原型仍未提供不可信网络 PBC 点解码。功能检查验证恢复的完整字节，原生群操作使用原来实际生成的类型化对象。这一范围不会写成网络服务已完成。
