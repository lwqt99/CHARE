# 主负载：真实资格撤销与证据

从 `chare-go-pbc-v0.4.0` 开始，配置中的 `revocations` 表示实际完成的 **1→0 资格变化**。调度标识为 `synthetic-active-only-slot-major-v1`。加密构造和序列化版本保持不变。

此前 v0.3.0 使用 `(attribute=step%m, slot=step%N)` 轮询发行拒绝记录。这是实际执行的更新，但可能命中本来就为 0 的资格。例如 N=4、m=2 的四次更新中，只有槽位 3 的 B 是有效撤销。旧结果仍然保留，不能把这些行重新标成四次有效撤销，也不能与新版本合并为重复样本。

## 新调度

初始资格继续使用原来的明确合成数据：`y[a][slot]=(slot>>(a%63))&1`。m=2、N≥4 时包含 00、10、01、11 四类；m=64 延续第 63 列重复第 0 列的旧夹具约定，不声称模拟现实属性分布。

测试控制器先按槽位升序、属性升序枚举初始为 1 的不同资格，取请求数量。该控制器知道合成真值，但这些真值不进入公共聚合、帮助生成或真实协议验证接口。输入规划是双方共同的测试准备，不当作密码学协议操作计时。

槽位从0编号，属性0/1分别表示A/B。N=4、m=2 的完整顺序为：槽位1的A、槽位2的B、槽位3的A、槽位3的B。第三次操作后槽位3仍有B；第四次后所有正资格均失效。N 为4的倍数且m=2时，初始正资格恰好N个，因此论文网格支持完整的N次有效撤销。

每次操作中，机构在持有人离线时实际生成新的拒绝记录和私密交付，目录验证、安装并发布当前快照；DH对照据相同状态生成自己的授权视图与epoch。持有人不参与更新，随后按同一个公共转录选择的获取调度刷新。所有旧状态继续保留。

如果请求次数超过初始正资格总数，配置预检查直接拒绝；不补零操作、不悄悄重新授予，也不缩短工作负载。重新授予和批量到期仍是另列的压力分支。

## 回传与检查

`manifest.json` 增加 `workload_schedule`。每个 `cases/<id>/result.json` 增加 `workload_evidence`，包括：

- 初始正资格数、请求和完成的有效撤销数、请求和完成的双方获取数；
- 每个事件的序号、槽位、属性、before/after、原版本、安装版本和快照序号；
- CHARE是否已安装、DH是否已发布。

出现中途错误时保留已执行的部分事件，案例失败，不进入成功汇总。只有全部事件均为不同的1→0、双方发布完成、获取次数匹配，案例才通过。Python读取新版本时再次核验事件；旧版本明确标记为未经有效撤销核验的历史调度。

这些是合成实验诊断文件，不能公开用作隐藏资格协议的一部分。操作计数、真值和错误诊断不属于论文的隐私转录。事件证据和功能测试也不是密码学安全证明。

## 测量解释

CHARE仍发布实际拒绝记录；DH可能改变多个策略名单，例如撤销A也会增加非A名单。两方费用按各自实际操作统计，不强行令相同标签代表相同工作。普通更新、重新授予、批量到期、全员追赶和冷审计不混成一个均值。

对新策略的代数组合只在已经准备好的固定候选集合与属性字典内复用。候选集合变化、完整上下文处理、来源验证和客户端下载仍收费。“两点密文核心”不能代替完整传输或新集合准备成本。

## v0.6.0 全员冷审计压力边界
主负载 R 次有效撤销与 A 次获取及全员追赶之后、独立批量失效/重新授予分支之前，执行 cold_audit。默认 paper 配置设置 cold_audit_all_users=false，只实测一个客户端；sanity 与非默认 paper-full 为 true，实际为每个槽位重复完整独立验证，不乘单次样本。初始与每次更新发行的公开历史均实际获取和重放，帮助由同一终点生成并核对。当前快照选择及注册发行权威仍是前提；审计不恢复隐藏事实。
