# 显式名单 DH：独立生命周期与计费

当前实现版本：`chare-go-pbc-v0.4.0`，独立生命周期在v0.3.0补齐；v0.4.0的有效撤销调度见[工作负载](WORKLOAD.md)。该生命周期实现了普通 source-DH 的实际注册、认证和状态交付，不改变 CHARE 的加密构造，也不增加论文创新主张。

## 输入和信任

两方案共享实际 Type A 群描述。DH 另行抽取自己的非单位基点、非零接收秘密和 Ed25519 认证密钥，不复用 CHARE 用户的秘密、公钥、投影、发行胶囊或目录签名。基点拒绝取样最多 1024 次；失败返回错误。所用随机源与具体安全强度的限制和主原型一致。

注册机构认证 `(完整上下文, 槽位, 固定接收键版本 1, Q=zG)`。上下文包含参数原文、群阶、基点、容量、属性数、认证公钥及固定策略清单。发行资格的真实性、身份核实的社会成本没有用程序实现。认证根和当前期望 epoch 预先可信；不能从下载内容本身取得信任或新鲜性。

**已决定的公开授权名单是外部输入。** `authorized_list_test_oracle` 遍历合成资格，为 A、非 A、B、A∧B 等固定策略准备名单。这部分实际执行并单列，绝不称为隐藏资格筛选。该对照的名单直接公开授权集合，原始 CHARE 的资格隐私要求不能据此转移给它。

## 实际状态机

目录先独立生成并认证全部接收键；发送方实际获取和验证完整接收键目录。普通客户端首次只获取自己的证书和当前 epoch，公开列表在有关密文上下文中取得。各方本地使用程序生成的类型化对象；没有实现任意网络群元素的安全反序列化。

每个固定策略有一个签名视图：完整策略编码、局部版本、升序无重复的 `(槽位,Q)` 数组。一个全局 epoch 绑定完整有序的策略—局部版本表。名单改变才产生新局部版本和签名；没有改变的 B 名单可在 A 撤销后继续使用。每次发布都实际签署全局 epoch，并发布所有改变的名单；空名单也是有效签名状态。空名单没有 KEM 锚点，因此不运行 anchored KEM。

`publish` 不读取用户秘密，仅使用公开注册键、已决定的名单和签名密钥。发布是原子的：任一名单缺项、乱序、重复、越界或版本溢出即失败，不能留下部分更新。注册键不可在本版直接轮换；重新授予仅增加授权状态版本，不伪装成接收键轮换实现。

发送方验证当前 epoch、策略视图及其键与已取得目录的一致性，再实际封装。完整签名 epoch 和策略视图以字面字节进入 KDF 上下文。接收方验证当前状态，再用自己的独立秘密解封装。低层 CPA 解封装函数可以恢复旧密文；当前状态拒绝不等于撤回过去明文，也不赋予 CCA 安全。

v0.4.0 主负载的每一次 CHARE 拒绝更新都撤销一个原本有效的资格，随后发布对应 DH 状态。旧版轮询中存在“原本已拒绝、名单未改变”的情况，旧结果保留其原始含义，不重新标记。两方案使用相同的公开转录选择请求槽位，分别执行配置指定次数的自适应获取。全员追赶、单客户端冷审计、重新授予另列压力模式。批量到期是独立分支，epoch 签名绑定不同历史命名空间，不会把分支状态接入主历史；程序也检查这种误用被拒绝。

## 输出和费用范围

所有时长来自真实执行，不以公式替代。不同操作的 bytes 可能分别是生成大小、网络获取大小或本地序列化，不能全部相加当作网络流量。

| operation | 实际工作与 bytes |
|---|---|
| setup_and_authority_keygen | 抽取基点、生成独立签名钥、组装公开上下文；bytes 为上下文 |
| user_keygen | 非零标量和实际 Q=zG；bytes 为槽位与短接收键框架 |
| root_certify / root_validate | 实际证书签名 / 完整上下文核验与验签 |
| registry_publish | 完整注册目录序列化，一次发布 |
| sender_registry_acquisition | 一个发送方实际复制全目录、逐证书核验 |
| authorized_list_test_oracle | 合成外部名单准备；不算隐藏筛选服务 |
| authorization_publish | 局部视图变化判断、变化名单签名、一次 epoch 签名；bytes 含完整实际发布 |
| first_acquisition | 每位用户验证自身证书、公私钥一致性、当前 epoch，并复制实际获取字节 |
| refresh / offline_catchup | 当前 epoch 的实际取得、验签；无需其他人的秘密和证书 |
| sender_authorization_acquisition | 一次策略视图与 epoch 的复制、认证、与已获取目录的键绑定核对 |
| receiver_authorization_verify | 每个列名接收者的状态验证；字节已在密文中，不重复收取网络费 |
| encapsulate / decapsulate | 独立 DH 键上真正执行；完整密文包含认证上下文 |
| cold_audit | 一个客户端实际重验全部证书、当前视图及键绑定，不称为全员审计 |
| retained_history_storage | 实际序列化证书与历次发布；不等于进程 RSS，不含私密状态 |

`CHARE-auth` 仅记录 CHARE 的机构、根与快照认证；不再使用可能暗示双方共同分摊的 `shared-auth` 标签。双方各有独立的前缀缓存签名与字节账本，仍按 TRANSPORT.md 区分完整传输和缓存传输，不能将两种配置相加。

令固定策略数量为 P、每次改变名单数为 h。该实现初始签署 N 份接收键证书、P 份视图和 1 份 epoch；后续每次发布签署 h 份视图和 1 份 epoch。判断未变名单仍真实遍历并比较相关字节，不能记作免费。每个列表包含它实际授权的用户数，整体名单及其首次获取仍随名单规模增长。完整上下文在多个证书/发布中重复出现，全部按真实字节收费。

主工作负载、策略封装、缓存重复封装及压力分支分别按 mode/operation 取数。不得把本程序用于检查实现而额外执行的解封装简单相加称为部署总时间。普通撤销与 regrant 均使用当前已经实现的显式名单输入，不把未实现的隐藏选择成本填零。

## 可以和不能得出的结论

现在可以比较两种已明确交付配置中的实际操作、通信与序列化存储，并给出自己的注册和认证成本，不再复用 CHARE 接收键后省略 DH 初始化。仍不能据此宣称功能等价、同具体安全强度、CHARE 有端到端优势，或该普通生命周期补全构成新密码学贡献。本文档和功能测试也没有提供新的安全定理。
