# CHARE：扩容与保留计划的真实配对参考执行

本目录为本轮新增的可复核执行。它复用上一轮公共恢复编译器，在真实椭圆曲线坐标和目标域元素上执行相同公式，并为扩容控制器保留逐事件日志。

## 运行

需要 Python 3.10 或更新版本。使用随包固定参数时只依赖标准库。

```bash
python3 type_a.py
python3 run_traces.py
python3 replay_public.py
```

从整个增量包的根目录运行时，在命令中加上 `verification/coordinate_pairing/` 前缀。各程序把结果写在其自身目录。`generate_parameters.py` 仅用于重新生成同一参数，额外需要 SymPy；正常重放无需运行它。

## 群运算

- 曲线为 `E/F_q: y^2=x^3+x`，`q=3 mod 4`，256位素数阶 `p` 整除 `q+1`，基域为1536位。
- 源群点只保存仿射坐标 `x,y`，目标群元素只保存 `F_q[i]` 中的两个坐标，`i^2=-1`。
- 使用畸变映射 `(-x,iy)`、Miller运算和最终指数 `(q^2-1)/p`。源码说明了省略基域垂直分母的依据。
- 点乘使用实际整数，不先把标量模 `p`，因此子群检查确实计算 `pP`。
- 本目录采用自己的明确编码和参考KDF域标签。结果检查针对本目录创建并保留原始上下文的密文。

构造依据为 PBC 官方 Type-A 文档及 Ben Lynn 博士论文：

- https://crypto.stanford.edu/pbc/manual/ch08s03.html
- https://crypto.stanford.edu/pbc/thesis.pdf

参数文件记录可复现生成过程与素性筛查。该执行用于验证群等式、来源连续性和准入逻辑；原稿已有的 Go 与 PBC 性能结果保持原统计口径。

## 三条轨迹，每条两个可复现测试种子

1. **安全增长。** 原容量 `N=6`，初始只生成节点1至4的核心；先发布 `(X-5)(X-6)`，随后新增节点5、发布 `X-6`，再新增节点6、发布常数方向。实际方向秩依次为1、2、3。原目标判据枚举各阶段的15、31、63个非空子集。另有一个旧预留计划在节点5出生前只发布部分贡献，并在五成员目标形成后用原pads完成。
2. **旧和约束新注册。** 四节点已发布常数和。正常控制器拒绝节点5；测试分支显式绕过该拒绝，形成五成员目标后使用旧和恢复该目标。
3. **待完成计划。** 常数和的严格前缀当前核心能力为零。只看当前能力的规则放行；包含旧计划的规则拒绝。测试分支让旧计划随后使用原partials与pads完成，恢复此前已形成的五成员目标。

每个新核心只在实际enrollment事件抽样，所有 `N-1` 根投影方程均以配对检查。Freeze检查新计划与当前及待完成方向的组合；Enroll执行公共零点准入。显式反例分支使用 `bypass_for_counterexample=True`，正常调用无法执行已拒绝的注册。

这些执行采用诚实canonical根、纯核心服务和空策略目标。Pads通过本地私有参与者状态安装；每次调用使用新pad身份。原论文的认证与交付测量仍由原Go工程负责，本文档记录的新增证据集中于群运算和控制规则。

## 公共重放与检查值分离

`public_recovery_inputs.json` 只含公共参数、根投影、保留输出、已知系数、原密文、原上下文和公开见证。其内容不包含核心、pad、setup或封装标量，也不包含fixture种子或预期密钥摘要。

`replay_public.py` 在独立进程中读取这些公共输入，并输出重建的目标域元素摘要与密钥摘要。它不导入生成fixture的harness，也不读取预期值文件。`expected_recovery_hashes.json` 仅供外部核对结果，`isolated_replay_check.json` 记录四个独立重放的比较。

`execution_results.json` 是完整事件账本，包含可复现fixture种子、真实点引用、source IDs、冻结与观察次序、注册决定、原target IDs及断言结果。可复现测试种子用于复核执行，不属于恢复编译器的输入。
